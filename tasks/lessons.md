# 교훈

## 외부 API 를 부르는 `--probe`/`--dry` 모드는 호출량 상한부터 설계한다
- 상황: 일일 1,000회 제한 API 의 probe 모드가 "첫 페이지만 확인"하도록 만들었는데, 이후 단계(상세 조회 루프)는 그대로 돌아 호출을 약 850회 소진했다.
- 규칙: 확인용 모드는 목록 조회뿐 아니라 **모든 루프**가 1~2건에서 멈추는지 코드를 끝까지 따라가 본다. 한도가 있는 API 는 실행 전에 예상 호출 수를 계산한다.

## 필터 휴리스틱은 실제 데이터로 먼저 눈으로 확인한다
- 상황: "누구나 관람", "축제", "체험" 같은 넓은 키워드로 거르자 서울 행사 300건 중 대부분이 아이와 무관했다.
- 규칙: 가짜 데이터 테스트를 통과해도 실제 응답으로 결과 제목 목록을 출력해 확인한 뒤에 기준을 확정한다.

## 샘플 데이터에 없는 필드는 테스트가 통과해도 실제로는 깨질 수 있다
- 상황: 샘플 데이터의 `image`가 전부 null이어서 이미지 로딩 경로가 한 번도 실행되지 않았고, 배포 후 실제 데이터에서 이미지가 하나도 안 떴다 (화면에 붙지 않은 `loading="lazy"` 이미지는 브라우저가 로드하지 않음).
- 규칙: 화면 코드는 배포 직후 **실제 데이터**로 한 번 더 확인한다. 샘플 데이터에는 이미지·링크 등 모든 필드가 채워진 항목을 반드시 하나 이상 넣는다.
